# Architecture Authority Migration

**Status:** in progress. This is the coherence plan for the current codebase, not
a claim that the migration is complete.

## Decision

SynTutor will have:

1. **One structural authority:** Burton-Roberts canonical tree.
2. **One approved grammar authority:** the independently reviewed Cambridge
   runtime registry.
3. **Legacy channels:** the legacy matrix, CoLA and raw Benepar parse remain
   available, but they are labelled diagnostic/candidate and cannot silently
   masquerade as approved Cambridge or verified B-R claims.

Do **not** delete the legacy detector before the replacement path is licensed
and tested. Today the legacy matrix is the only production detector; Cambridge
has all 193 implemented pilot rules enabled as owner-waived, AI-checked candidate rules; they are not independently human-certified.

## What changed in the first slice

- `server/authority.py` builds an explicit authority manifest and attaches it to
  `/api/parse` as `authority`.
- `server/canonical_binding.py` binds each legacy detail to a canonical node
  (`canonical_node_id`) using remediation edit targets first, then token spans.
- The UI uses that backend binding first (`web/js/legacy-node-map.js` fallback
  remains for older payloads).
- Legacy diagnostics are shown only on the exact target node, never inherited by
  every descendant or ancestor.
- The tree authority notice now states the structural, detector, Cambridge and
  candidate channels.
- The legacy diagnostic card is labelled “Legacy diagnostic — not
  book-verified”; it is not mixed with Cambridge or B-R claims.

## Second slice: disposition and unified findings

- `tools/legacy_disposition.py` generated
  [`legacy_rule_disposition.json`](legacy_rule_disposition.json) for all
  **112** legacy rules: 62 are proposed `port_candidate`, 50 are proposed
  `keep_legacy_diagnostic`. These are proposals requiring review, not final
  decisions.
- `server/findings.py` builds a unified finding list. Every item carries
  `authority` (`legacy_matrix` or `cambridge_candidate`) and `claim_status`;
  legacy items retain their canonical node binding, and candidate items remain
  non-production.
- `/api/parse` now returns `unified_findings` alongside the existing
  `node_details`, `candidate_xai` and `authority` fields.

## Gold baseline

`evaluation/br_final_d1_gold.json` now holds 20 entries from the declared
held-out sentence file. It is an **AI adapter-derived baseline with owner-waiver
provenance**, not independent gold. `scripts/report_br_final_d1_gold.py` reports
exact adapter drift and labels the caveat. The master list's non-adapter-derived
gold, near-negative and accepted-alternative requirements remain outstanding.

## What remains

### 1. Canonical routing

The legacy matrix still runs on Benepar. The next structural step is to run the
matrix and candidate probes on the same canonical B-R tree (or an explicitly
declared projection) rather than bridging Benepar findings after detection.

### 2. Legacy rule disposition

For each of the 112 legacy rules, choose one:

- **port** to a Cambridge-backed rule with source, crosswalk, implementation and
  tests;
- **keep diagnostic** as a legacy-only check with no book-verified claim;
- **retire** after the replacement passes parity and held-out tests.

Do this rule-by-rule. Do not delete checker code until its replacement is
tested.

### 3. One production pilot family

Pick one small high-confidence Cambridge family, complete independent review,
resolve the B-R crosswalk slice, add held-out tests and enable it in
`grammar/runtime_registry.json`. Use that as the template for the remaining
candidates. An implementation cannot self-certify review.

### 4. B-R adapter completion (Benepar remains the parser)

The final target convention in
[`ABSOLUTE_SYNTAX_MASTER_LIST.md`](ABSOLUTE_SYNTAX_MASTER_LIST.md) keeps
Benepar as the general English parser. The required work is the Benepar-to-B-R
adapter, not a second unrestricted parser. Complete the construction table for
S02–S10 and P01–P09, preserve unresolved/working status where the adapter
cannot justify an analysis, and evaluate exact complete trees on frozen gold
suites. A native parser is optional research.

### 5. Lessons and quizzes

Excluded from the current migration by owner decision. Keep the existing
content until a later pass.

## Coherence invariants

- Every user-visible claim states its authority.
- Candidate and legacy findings are never called “verified errors.”
- A node shows a legacy diagnostic only when that node is the exact target (or
  the smallest covering node when no target exists).
- Cambridge runtime activation requires independent review, a resolved
  crosswalk, deterministic implementation and passing tests.
- Production remains fail-closed while the registry is empty.
