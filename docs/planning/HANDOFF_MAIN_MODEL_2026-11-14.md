## 1. What is complete

### Runtime and detection

- All **193 implemented Cambridge pilot rules** (187 primary + 6 supporting) are
  enabled through an allow-listed Phase-C candidate set.
- The 11 deferred semantic specifications are ignored by owner decision.
- Runtime rules are recorded in `grammar/runtime_registry.json` and
  `grammar/cambridge_runtime_overlay.json` with:
  - `owner_waiver: true`
  - `independent_review: false`
  - `crosswalk_status: owner_waived_unverified`
  - `test_status: source_examples_passed`
- The runtime executes one candidate probe set per normalized sentence and
  filters findings by rule id.
- Legacy matrix findings, Cambridge candidates and unified findings all carry
  explicit authority and claim labels.

### Canonical tree and held-out coverage

- **281/281 grammatical held-out sentences normalize** to a B-R tree.
- **0 false positives** on the 281 normalized grammatical sentences.
- **45/45 ungrammatical held-out sentences have a tree**: 29 normalized,
  16 explicit working trees.
- No held-out sentence is left without a tree.
- formerly working constructions now normalized include:
  - negative focus (`not even NP`);
  - comparative clauses (`taller than`, `as old as`, `more plays than`);
  - comparative object gaps (`such cakes as she made`);
  - complex-object extraposition (`find it odd that…`);
  - parentheticals (`My aunt – she lives in Paris – is visiting`);
  - topicalization (`This book I gave to Mara`);
  - temporal coordination (`tomorrow or on Friday`);
  - subjunctive `be`/base clauses (`It is vital that he leave early`);
  - idiomatic wh-question (`What is the matter, that…`).

### Authority and XAI

- `server/authority.py` exposes the runtime authority manifest.
- `server/canonical_binding.py` binds legacy details to canonical nodes.
- `server/findings.py` builds unified legacy/candidate findings.
- `server/cgel_candidate_xai.py` maps candidate findings to canonical or
  Benepar nodes and composes candidate-only explanations.
- UI red marks use the same legacy remediation targets/candidate token bindings
  as the input highlighting.
- Legacy/candidate explainer labels and book/certification disclaimers were
  removed from the learner-facing explanation, as requested.
- Removed the authority strip, Builder prompt, tree help paragraph and English
  variety selector from the UI.

### Source and disposition work

  - 252 record decisions;
  - 130 uncovered-instance dispositions;
  - 126 chapter-only, 4 source anomalies, 0 unresolved.
- `docs/planning/legacy_rule_disposition.json`:
  - all 112 legacy matrix rules accounted for;
  - 62 proposed `port_candidate`;
  - 50 proposed `keep_legacy_diagnostic`.
- `CONVENTIONS.md`, PR #169 audit/adapter files and the 20-sentence held-out
  file are included in the working tree.

## 3. What was not accomplished

### 3.1 Exact tree work

- The 11 exact mismatches have not been adjudicated against their chapter
  profiles.
- The 29 unresolved source fixtures still need figure/path-level analysis.
- `evaluation/br_final_d1_gold.json` is an **AI adapter-derived baseline with
  owner-waiver provenance**, not non-adapter gold. It has:
  - 20/20 normalized entries;
  - no near-negative cases;
  - no accepted alternatives;
  - no independent authoring.
- The 20/20 adapter match is circular drift checking, not accuracy evidence.

### 3.2 Non-adapter gold and held-out accuracy

Still missing:

- complete ordered trees authored from fixtures + `CONVENTIONS.md`, not adapter
  output;
- near-negative pairs for every supported construction;
- accepted alternatives and ambiguity cases;
- development and frozen held-out splits;
- false-canonical rate, ambiguity recall, exact-match denominators and latency
  reporting for the final gold suite.

`PHR-612`, `PHR-655`, `PHR-656`, `PHR-673`, `PHR-696`.

The grammatically correct side is fully normalized (281/281). The working

### 3.5 Main-model workstreams

Not fully completed:

- **S02** — full adjudication of all 252 source records against profiles.
- **S04–S10** — complete construction table, feature projection, tokenization,
  ambiguity/alternatives, provenance, pagination and public contract.
- **P01–P09** — full Benepar→B-R transformation table, lexical frames,
  NP/VP/clause transformations, gap/control/co-index licensing, local
  validation, alternatives and Penn/model-score isolation.
- **U01/U02/U04/U05/U06/U07** — Generator status/uncertainty, Builder
  round-trip, XAI source tying, correction semantics, transport/storage audit,
  documentation reconciliation. U07 is partially updated.
- **U03** — lessons/quizzes, excluded by owner.

### 3.6 Production quality risks

- All 193 runtime rules use owner-waived AI checks and source-example/guard
  tests. They are **not** independently reviewed or held-out-validated.
- The runtime candidate set has no per-rule precision/recall measurement.
- The held-out ungrammatical corpus is legacy agreement data, not a balanced
  Cambridge candidate corpus; 0 Cambridge findings there is a coverage
  statement, not detector accuracy.
- No latency benchmark for running the candidate set per sentence.
- No independent source/crosswalk certification; owner waived human review.
- The legacy matrix remains the only legacy production detector and still runs
  on Benepar, not the canonical B-R tree.
- Full contract/storage migration is not proven; existing contract tests pass
  but old consumers/export paths were not exhaustively audited.

### 3.7 UI/UX

- The requested explanatory labels were removed, but no browser/Playwright run
  was possible because Playwright/Chromium is not installed in this
  environment.
- Input/tree red-mark parity was implemented and JS-tested, but not visually
  verified in a browser.
- No accessibility/screenshot pass on the new explanation layout.
