# SynTutor end-to-end technical evaluation methodology

**Thesis:** *SynTutor: An Explainable AI-Based Framework for Syntax Tree-Driven Grammar Analysis and Learning Using NLP*  
**Status:** Proposed primary technical protocol and read-only reference audit. All 24 pilot inputs have been inspected. The pilot and primary study are unrun. [Readiness report](SYNTUTOR_END_TO_END_EVALUATION_READINESS.md)

## 1. Research question and scope

The primary technical question is whether SynTutor reliably carries syntax-tree and grammar evidence through analysis, correction, and learner-facing explanation across a declared set of workflows. The unit is a scenario from submission through rendering or recovery, including selected-node explanations. The independent linguistic question is how often the resulting tree, rule application, correction and explanation are jointly correct for the sentence. That question needs complete references and has no eligible pilot cases. Component benchmarks supply bounded linguistic comparisons alongside the integrated measurements.

The primary intended scope is edited standard written English under the free-analysis FINAL-D1 Burton–Roberts profile, including ordinary learner errors and explicitly sampled boundary cases. Preserve an input's original text, register, and any documented context. Predeclare narrowly supported constructions and accepted variants from the reference sources, then map them to the enabled implementation for reporting. Distinguish an English construction the product cannot analyze from an English sentence that violates a grammatical constraint.

| Claim | Required evidence |
| --- | --- |
| Technical correctness | Observable contract and invariant checks for requests, source offsets, tree serialization, rendering, selection, and status propagation |
| Explanation faithfulness | The displayed claim accurately reflects the recorded source span, tree relationship or rule evidence and its actual authority. A new controlled contrast can test responsiveness to evidence. This measures fidelity to observable analysis. |
| Linguistic correctness | Independent confirmation of the actual constituent, rule application, claim and correction on the specific sentence, including valid alternatives |
| Educational effectiveness | A separate study of learner outcomes, such as accurate rule application on new examples or delayed retention. Readability, perceived clarity, and a technical pass are different measurements. |

The study can demonstrate a faithful explanation of an incorrect parse. Score that as a faithful trace and a linguistic failure. Likewise, fluent correct prose can fail faithfulness when it cites the wrong evidence or claims a rule ran when it did not. Keep grammar-rule evidence from the Cambridge or deterministic channels identifiable. Report advisory RoBERTa acceptability and candidate-only findings separately from confirmed errors.

## 3. Independent reference specification

Lock references before the analysis is shown to their annotators. A reference is specific to an item, output and scope. A book chapter can independently establish a general principle. Applying that principle across a novel sentence requires an explicit, source-cited interpretation and consideration of exceptions. An authentic corpus annotation supplies only the information its annotation scheme records.

| Layer | Reference answer required | Valid partial reference |
| --- | --- | --- |
| Tree | Original printed B–R third-edition figure for that exact input and used labels, independently transcribed from the original with a figure/page locator, or a blind, source-cited new analysis produced by a qualified annotator and checked independently. Preserve licensed alternate trees, features, gap anchors and antecedent links. Declare the FINAL-D1 mapping decisions independently of the output. | Published figure with triangles supports constituent labels and boundaries outside collapsed interiors. A cited Cambridge dependency can verify a relation. Penn/GUM trees can verify Penn structure under their conventions. These three cases support different claims. |
| Grammar and rule application | Item-level judgment under a named standard/register, explicit applicable construction and exception, and expected error type, target and supporting role or licensed alternatives. Use Huddleston and Pullum's CGEL with chapter/section/page citations or a trusted published annotation whose scope matches the claim. | BLiMP acceptable/unacceptable reference for the contrast. W&I or EXPECT annotation for the marked edit or type. Neither provides a complete inventory of every error in an item. |
| Correction | Pre-specified acceptable source-span edits or reviewed whole revisions, protected meaning constraints (entities, polarity, tense, argument roles, quantity) and guidance on whether omission of a correction is warranted. Context-sensitive and equally defensible alternatives can be recorded. Capture whether each correction is complete, valid partial, unnecessary, meaning-changing, introduces an error, or cannot be adjudicated. | An authentic M2 replacement or a published revision is a matchable reference. An additional novel replacement needs independent judgment before the score can credit it as meaning-preserving. |
| Explanation | Item-level required, permissible and forbidden propositions with source-located justification and evidence spans. Annotate whether each proposition applies at sentence, constituent or word level. Address the role of nonerroneous witnesses, scope of correction and uncertainty where relevant. Score propositions rather than exact wording. | EXPECT word anchors and evidence allow span comparisons. Source-cited role statements may permit partial correctness scoring. A prose sample, general grammar rule, or fact graph is insufficient to validate all assertions for a specific sentence. |
| Uncertainty and unsupported input | Independent classification of relevant ambiguity/coverage and a versioned response policy. Record accepted readings, whether a qualified alternative suffices, and which claims or edits lack evidence. For unsupported inputs, confirm the scope reason independently of the observed response. | The API contract verifies graceful behavior for invalid or unavailable requests. Such tests have no grammatical judgment reference. |

Use B–R for canonical structure and CGEL for the named grammatical principles, with explicit crosswalks where the reference formalisms or categories differ. A local registry match establishes which implemented rule fired. Owner-waived curriculum material, AI-generated gold derived from the FINAL-D1 adapter, self-correction reanalysis, and agreement between output channels do not establish linguistic correctness. A Cambridge excerpt may be evaluated under its original conventions without translating it into gold B–R labels. Record edition and page, source rights and use restrictions. Store locators and digests for restricted figures and keep the material in an authorized evidence pack. [B–R third-edition bibliography](https://catalogue.bnf.fr/ark%3A/12148/cb42336036b), [CGEL at Cambridge](https://www.cambridge.org/core/books/cambridge-grammar-of-the-english-language/A78402ABF5176AD283494180BCA2046F), [repository convention decisions](../canonical-burton-roberts-tree-schema.md), [handoff review](SYNTUTOR_INDEPENDENT_AGY_HANDOFF_REVIEW.md)

Each reference record should store `case_id`, exact source text/context and character offsets, original corpus/document/figure identifier, reference revision and digest, register and construction, accepted and excluded readings, per-layer status and scope, expected facts or spans, source locator, author/reviewer identifiers and conflicts, and a source-based rationale for adjudication. Use `DIRECT` for a matching published annotation or transcribed source, `ADJUDICATED` for a newly reviewed interpretation, `UNVERIFIED` for missing or unresolved answers and `N/A` for a dimension declared inapplicable before the run. Reference status belongs to the study. Application abstention is a different field.

### Selection, exposure and freeze

1. **Provisional screening completed here.** Compared punctuation/spacing-insensitive, casefolded Unicode-normalized text against 1,188 readable checkout or selected Phase 2–3 artifact files, covering scripts, benchmarks, tests, documents, case JSON and saved prediction/trace data. JSON/CSV/TSV text extraction and quoted example extraction yielded 33,045 distinct token sets for a Jaccard screen at 0.85. BLiMP entries were ranked within the chosen paradigm using SHA-256 of `syntutor-e2e-pilot-v1:<UID>:<pairID>`. The parent W&I sampling restricted source lengths and selected single-edit annotations by type and hash. The reflexive pair and two EXPECT learner examples were adjusted to cover local evidence types and passed both follow-up checks. The four adjusted inputs' maximum Jaccard similarities ranged from 0.2143 to 0.3077. ## 5. Linguistic scoring rubric and denominators

Apply this rubric only to the specific reference scope documented in §4 or to eligible supplemental benchmark data. The full end-to-end linguistic score described here has no present denominator. The independent reference gate applies to future work. It does not prevent the primary technical study.

Use four review marks for each required check, **pass**, **fail**, **unverified**, and **inapplicable by prespecified scope**. A system omission with an independently known and required answer is a failure for that dimension, with abstention separately recorded. Missing independent gold is unverified. Partial findings are scored at their verified scope. Record severity and provide the conflicting source span and rule or reference for every material failure. Any harm classification based on human judgment needs independent review.

| Criterion | Observable check and case pass condition | Reported estimates |
| --- | --- | --- |
| **Syntax-tree accuracy** | Validate original lexical yield, offsets, well-formed structure and true status against contract. Then compare verified labels and boundaries, head/argument relations, clause types, features and movement/ellipsis links against source analysis. Respect unexpanded gold triangles and licensed alternate structures as wholes. A valid alternate may pass if frozen in advance. A canonical claim with material unsupported labeling, a missing required constituent, or a wrong antecedent fails the relevant check. | Status rate for all eligible requests, gold availability rate, label/span P/R/F1 on aligned and reference-eligible inputs, exact **scored** span agreement and whole-tree agreement separately, and feature/link accuracy where gold exists. Report an intention-to-score span recall using all comparable structural gold spans, with missed spans charged to required but unavailable trees. Cases without a comparable mapping stay explicitly unresolved and count in coverage. |
| **Grammar and rule application** | Match submitted case verdict and confirmed findings to the independently annotated constraints. Match findings one-to-one by construction, target span or approved alternative and relevant participant role. Extra false findings fail even if the verdict is right. Advisory evidence cannot satisfy the required rule check. For references with only one local annotation, omit whole-sentence specificity and avoid judging other findings absent an exhaustive reference. | Verdict confusion table and separate abstentions and execution failures by gold class. Report decisive P/R/F1, MCC, specificity and class-wise coverage, plus end-to-end error recall whose denominator includes required findings missed under abstention or execution failure. Finding P/R/F1 uses adjudicated matches, spurious diagnoses and missed diagnoses, with explicit unknown extras when gold is local. |
| **Correction validity** | Check necessity, edit application to the original offsets, target resolution, grammaticality in context, protection of meaning, and absence of introduced errors. A valid partial correction passes the local edit check and must expose unresolved issues. It fails complete repair where the reference required a feasible whole repair. Where the reference says intent is underdetermined, a qualified alternative may pass the restraint check. | Per-edit precision/recall/F0.5 against exact corpus edits as supplemental evidence. Separately report independently acceptable edits over assessable proposed edits, introduced-error and meaning-change rates over assessable revised sentences, unnecessary-repair rate over verified clean inputs, and coverage of independently feasible repairs. Include all unreviewed proposals and abstentions in coverage counts. |
| **Explanation correctness and faithfulness** | For each required view, enumerate atomic propositions. Check that actual evidence can be traced via the source offset, node, edge or finding. Independently verify that each material statement is true for the sentence and that required evidence is explained. Extra incorrect statements, confused authority, agreement by proximity, or overclaiming based on a provisional tree fail their respective checks. Keep an explanation of a valid partial correction separate from a claim of whole correctness. | Report reference-proposition precision and coverage with defined material omissions, evidence word/span P/R/F1 when annotated, and rate of traceable emitted claims. Also report sentence-level counts of any false, unsupported or authority-mislabeled claim. Group atomic claims by case for intervals. Hygiene and readability can be diagnostic secondary measures. [GMEG-EXP human evaluation dimensions](https://aclanthology.org/2024.lrec-main.688/) |
| **Cross-output consistency** | The generated tree, highlights, finding, correction, evidence view and explanation refer to the same input and occurrence. Check JSON against the browser for the original request, node ID and source span, including Unicode offsets, related versus erroneous tokens, validated edit replay, provisional labeling, and clearing/replacing stale selections. A contradiction between authorities can be presented when qualified. Internal parity does not independently validate a linguistic answer. | Per-case rate of any material contradiction and separate invariant pass counts with applicable denominators. Track technical failures across all submitted requests. Report each mismatch with request/response and view evidence. |
| **Uncertainty, unsupported scope and technical recovery** | Compare reported certainty and specificity to the independent reading set and predeclared scope policy. Withhold definitive analysis where references require qualification, and keep independently justified local evidence when structure is provisional. Distinguish linguistic ambiguity from failed requests and infrastructure errors. | Decisive coverage and risk given a decisive outcome, abstention by reference truth class and reason, correct uncertainty and false certainty in reference-eligible ambiguous/unsupported cases, and missed findings when abstaining on supported cases. Correctly qualified cases are scored as uncertainty successes under their own denominator. |

**Joint outcome.** For in-scope cases, full success requires every predeclared applicable dimension to pass, with no critical false claim or harmful edit. A necessary correction can be inapplicable for a verified clean control. Form the fully referenced cohort from the frozen reference files before opening predictions. Report complete passes divided by all cases in that cohort, with technical failures and required-output abstentions in the denominator. Outside that cohort, report known failures alongside unresolved cases with missing reference answers. For all prespecified in-scope cases show the lower bound `verified passes / in-scope submissions` and upper bound `(verified passes + unverified cases without a known failure) / in-scope submissions`. These are missing-reference bounds, separate from sampling uncertainty. Report independently approved uncertainty responses in a boundary cohort. An optional policy-appropriate joint rate may combine in-scope and boundary cases with their different required outputs and frozen weights. It must show the two rates separately to keep restraint distinct from full resolution. Show the number that contributed to each dimension, the number with full references, and the raw counts for pass/fail/unverified/inapplicable. A zero denominator yields an unavailable estimate.

**Feasibility success.** The later pilot requires an explicit per-layer status, auditable provenance, preserved raw payloads and a reproducible reason for every missing comparison. Check all applicable published labels, edits and witness sets without adjudicating missing gold. Keep qualitative examples described as observations. A future fully referenced linguistic study would predeclare meaningful full-correctness and coverage thresholds and a tolerable critical-error rate tied to claim scope and risk.

**Size and uncertainty.** The 24-item pilot is a workload and rubric test, not a precision calculation. Measure annotation time, agreement/disagreements, referenceability, abstentions, failure rarity and clustering. For a final independent proportion estimate, choose a defensible 95% confidence interval half-width `w`. The conservative planning approximation `n ≈ 1.96²/(4w²)` gives about 97 independently referenced cases for ±10 points or 385 for ±5 points, under simple random sampling. Use finite-sample intervals such as Wilson for independent proportions and exact one-sided bounds for a rare high-severity event when justified. Even zero observed critical errors in 24 independent cases leaves an exact 95% upper bound of about 11.7%. Under the same independence assumptions and zero events, 59 cases are needed to bound that rate below 5%. Inflate recruitment for missing references and clustering, and allocate enough cases to each construction and boundary stratum for the claims planned. Quote document/pair-cluster intervals for correlated items and resample the entire sentence for nested edits, claims or nodes. A balanced challenge set yields a stratum-conditional estimate. A real-world estimate requires a target population and justified weights or probability sampling. For a paired version comparison predeclare a meaningful difference and power using the expected discordant cases, then use a paired case or cluster analysis. [NIST, *Estimating Instrument Performance with Confidence Intervals and Confidence Bounds*](https://nvlpubs.nist.gov/nistpubs/TechnicalNotes/NIST.TN.2119.pdf)

### Pass rules, coverage and reporting

1. **For each scenario, predeclare required checks before a run.** A normal request passes only if transport and input identity succeed, applicable envelopes and offsets meet contract, and required UI actions render the same source, current node and rendered authority/status. Verify that displayed findings reference existing tokens or nodes as appropriate and that target and related witness roles are kept separate. If a correction is offered, replay the declared edits on the original selected text in the declared offset convention. Compare with the shown revision and enforce the stated partial/complete status. Identify any allowed formatting normalization before scoring and fail unexplained changes. The replay checks consistency between strings, not whether the repair is defensible English. Where the backend says provisional or unavailable, the UI must indicate that status and preserve any independently gated structured local evidence present in the payload. [Canonical contract](../canonical-burton-roberts-tree-schema.md), [transport](../../server/webapp.py#L106), [shared payload](../../server/analysis_api.py#L157)
2. **Require delivery of the named sentinel pathways.** Define four beforehand from development scenarios. `canonical` must make the canonical view available, `auxiliary` must show provisional structure and available local evidence together, `quantified-agreement` must exercise correction, and `stranded-recipient` must exercise selection of the preposition. Score whether the declared capability is delivered, independently of whether the grammatical analysis is correct. Report sentinel pass over **4**. Missing that pathway fails its scenario. Otherwise a system could pass every applicable check by supplying no tree, actionable finding, or selected explanation.
3. **Report a fixed-denominator result.** Report passing scenarios divided by **18**, with separate counts for normal requests (**15**), boundary/race (**2**) and Builder (**1**). For the normal requests, separately report usable analyzable responses, canonical/provisional/unavailable tree counts, decisive/unverified verdicts, exposed corrections and evidence-bearing explanations, each over **15**. Give the count of actual delivered artifacts and their applicable integrity checks, such as successful edit replay over all exposed revisions and valid node links over all comparable links. Missing a required view is failure, optional absence is measured as coverage, and unmatched prose lacking a comparable evidence link is reported as unassessed. When a normal request fails technically, count it separately rather than calling it a linguistic abstention.
4. **Validate the evaluator with six technical controls.** Use an unchanged valid contract fixture and five deliberate variants with a wrong source occurrence, a dangling node link, a provisional view presented as canonical, an edit replay discrepancy, and a stale response. Require the valid control to pass and all five faults to be detected. Select the mutations from deterministic software facts, not from English judgments. Report **correct control classifications / 6**, separately from the 18 workflows, and list which predicate each control exercises. A technical check cannot detect a linguistically false but consistently reproduced claim. Record a known type of such case when demonstrating the protocol's limits.
5. **Use a deterministic acceptance gate.** Pass this finite conformance suite only when all 18 planned scenarios pass their required checks, all four pathways are delivered and all six checks of the evaluator have the prescribed outcome. Count failed, blocked, and unattempted scenarios explicitly in `18 = pass + fail + blocked + unattempted`. A blocked run cannot pass by shrinking the denominator. Record the first attempt as primary and report any allowed rerun separately. Coverage is empirical for this scenario manifest. No statistical claim about general reliability, novel grammar, or pedagogical effectiveness follows from meeting a finite contract gate.
