# SynTutor: 26-sentence end-to-end alignment audit

## 1. Test environment and execution

- **Checkout:** `fix/syntutor-system-reliability-xai`, commit `05dfdf0f9d731d8ad783b5d6b50e55cbbb08f30f`; clean before the audit.
- **Execution:** 26/26 executed, 0 blocked. One local CPU batch (~34 s including model loading), calling the production backend entry point `server/analysis_api.py::build_payload` once per original input, without asterisks. Free analysis used Burton–Roberts (B–R) `FINAL-D1`, with no explicit variety selected. Linux, Python 3.12.3, spaCy 3.8.16 (`en_core_web_md` 3.8.0), Benepar 0.2.0 (`benepar_en3`), Transformers 4.46.3, PyTorch 2.15.0. Models were local; the advisory RoBERTa CoLA channel returned a result for all 26. No installs, mocks, or source changes.
- **Evidence:** Inspected canonical, working and raw Benepar trees; main and canonical verdicts; findings, spans and learner node markings; XAI evidence; and revision/impact fields. The browser opts into candidate XAI, so its exact optional backend helper was also run over the captured trees without another parse or model load. It returned only two observations (#9, #18), both explicitly non-production and mapped to raw Benepar nodes. Highlighting was checked in the payload, not by clicking through a live browser. This is a targeted standard-written-English stress set, not a representative accuracy sample or a set of independently adjudicated gold trees.
- **Status and grading:** **N** = normalized and structurally validated canonical tree, not proof of linguistic correctness; **W** = unresolved canonical analysis with a provisional working tree; **R** = unresolved with only raw Benepar available. **PASS** requires observed evidence for the target; **PARTIAL** means useful but incomplete or qualified; **FAIL** includes wrong output or absence of a required diagnosis/repair. A justified decision not to invent context is not a failure. XAI passes only if it explains the *specific error* using the relevant canonical relationship and verified rule evidence; a span mapped to a canonical node is not enough. End-to-end **PASS** requires all four passes; **FAIL** denotes a material contradiction, wrong diagnosis/repair or a missed clear construction with no useful target feedback; otherwise **PARTIAL**.

## 3. Cross-component inconsistency findings

1. **High — Confident but wrong diagnosis or repair (#5–6, #9).** In #5 a generic reflexive fallback converts *himself* to nominative *he* rather than preserving object binding ([`matrix.py:1321–1333`](../../server/matrix.py#L1321)); the assembler did not publish that as a sentence. In #6 the stack check counts determinatives and its remedy deletes later ones ([`matrix.py:2790–2827`](../../server/matrix.py#L2790), [`3995–4013`](../../server/matrix.py#L3995)); revalidation accepts the quantifier loss. In #9 both auxiliaries attach to `swim`, but the run-on guard only exempts an auxiliary whose head is the *next finite item* ([`ruleset.py:2924–2964`](../../server/ruleset.py#L2924)); that item is `can`, not `swim`. The correct candidate-only observation and the wrong production diagnosis coexist.
2. **High — Valid structure flags coexist with wrong linguistic relationships (#14, #20–22, #26).** #14 calls the same verb transitive in the tree and intransitive in detection. #20 adds an indexed gap beside overt `it` and the resumptive check’s object list excludes `it` ([`ruleset.py:3607–3647`](../../server/ruleset.py#L3607)). #21–22 fall through to object-gap projection rather than recognizing the intended embedded object/subject dependency ([`final_d1_projection.py:2913–2971`](../../server/final_d1_projection.py#L2913)); #22 already receives demonstrative *that* from Benepar. #26 preserves the incompatible order as two independent adjuncts. Schema validation did not settle any of these relationships.
3. **High — “Grammatical” prose survives uncertainty or missed rules (#7, #13, #20–22, #24, #26).** The clean-matrix sentence “every word is used in an allowed way” is retained even when `detector.combine` changes the verdict to `unverified` ([`matrix.py:4641`](../../server/matrix.py#L4641), [`detector.py:118–144`](../../server/detector.py#L118)). In #7 the advisory label is unacceptable but its score does not trigger the downgrade. In #24 head lookup returns through the no-head acceptance branch **before** the later singular-quantifier rule ([`matrix.py:2539–2544`](../../server/matrix.py#L2539), [`2647–2657`](../../server/matrix.py#L2647)); CoLA also accepts it. Honest abstention is not the problem; the conflicting or overconfident text is.
4. **High — Explanations combine incompatible roles or omit evidence (#11–12, #16–17, #23, #25).** In #16–17 a dependency relation treats the nonfinite subject as requiring nominative case without checking the governing construction ([`findings.py:419–428`](../../server/findings.py#L419)). #17’s error mark is on *him*, not the *to* its own instruction says to delete. #11’s learner mapping usefully recovers *went*; #12 marks only *was* as erroneous despite recognizing *wrote* as the wrong form. #23’s local agreement finding is correct but the structural text mischaracterizes dummy *there*; #25 has a canonical binding in unified findings but no corresponding learner finding. The backend exposed these mismatches; actual rendering was not tested.
5. **Medium — Text advice, validated edits and source verification are different outputs.** #3 and #18 each count two resolved diagnostic entries for one error. #12, #14, #16 and #17 have no assembled repair, not a failed reparse; #16–17 have actionable prose but no structured edit from their detecting rules ([`ruleset.py:2309–2325`](../../server/ruleset.py#L2309), [`2361–2381`](../../server/ruleset.py#L2361)). All 12 emitted revisions passed local revalidation, including the meaning-changing #6 and the emphatic #8. The validator reparses and checks applicable channels, but does not check meaning preservation; the displayed impact reruns the matrix ([`analysis_api.py:417–443`](../../server/analysis_api.py#L417), [`696–716`](../../server/analysis_api.py#L696)). All 26 main verdicts were labeled `legacy_diagnostic`; there were no Cambridge runtime violations, XAI4 findings, or XAI7 verified issues. The canonical grammaticality field was `unresolved` for all 26, including normalized trees.

## 5. Final verdict and priorities

**0 of 26 fully aligned; 14 partial, 12 fail, 0 not tested.** The service returned 16 structurally normalized canonical trees, 9 provisional working trees and 1 raw-only analysis. The main verdicts were 19 `ungrammatical`, 5 `unverified` and 2 `grammatical`; these are output counts, not accuracy estimates. Several local diagnoses and repairs were useful, but no case supplied verified error-specific XAI grounded in a defensible canonical tree. The four components were **not consistently aligned on this set**. That is not a general English accuracy estimate or a contradiction of the manuscript’s benchmark scores.

1. **Stop wrong teaching advice first:** arbitrate contradictory verdict text and candidate/legacy findings; fix auxiliary-question and nonfinite-case scoping (#7, #9, #16–17, #24).
2. **Check repairs for the intended meaning and slot:** reorder instead of deleting quantifiers, keep reflexives in the licensed object position, and prefer neutral reported-question repairs unless emphasis is intended (#5–6, #8).
3. **Validate the grammatical relation, not only the tree shape:** check valency, overt versus gapped arguments, embedded dependencies, and degree attachment; fall back to a labeled working tree when these cannot be established (#14, #20–22, #26).
4. **Tie each learner finding to one target, its witnesses, and its edit:** distinguish provisional highlighting from verified canonical grounding; deduplicate findings and turn safe prose advice into structured edits where appropriate (#3, #11–12, #17–18, #25).
5. **Add a same-sentence alignment measure to the next study:** independently adjudicate reference analyses, variety-sensitive items and appropriate abstentions; report cross-component alignment separately from benchmark F1, clean feedback, provenance and revision stability.
