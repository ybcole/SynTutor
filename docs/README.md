# SynTutor

Explainable AI–driven intelligent tutoring system for English grammar. SynTutor replaces opaque "black-box" grammar tools with a transparent, deterministic pipeline: it parses sentences into **phrase-structure syntax trees** with a neural constituency parser, validates every structural dependency against a **Linguistic Constraint Matrix**, and explains each relationship in plain language.

Stack: **vanilla ES-module front end** (HTML5 `<canvas>`) + **spaCy + benepar** Python backend (`benepar_en3`). The tutor explanations themselves are generated by a **deterministic rule matrix** — no generative model is used for feedback, so identical inputs always produce identical verdicts (no hallucination). Test suites are intentionally excluded from the repository.

Docs: [`ARCHITECTURE.md`](ARCHITECTURE.md) is the full implementation reference (modules, FSM, layout math, payload contract, spec-compliance map) · [`RULES.md`](RULES.md) is the complete rule-matrix inventory · [`FEATURES.md`](../FEATURES.md) is the current feature and progress status.

## Quick start

Requires Python 3.10+.

```bash
# 1. install the NLP pipeline
pip3 install -r requirements.txt
python3 -m spacy download en_core_web_md
python3 -c "import benepar; benepar.download('benepar_en3')"

# 2. run the server
python3 server/app.py        # or: npm run serve
```

Then open `http://127.0.0.1:8000`. The workbench requires an authenticated
Supabase session. Before starting the server, copy `js/config.example.js` to
`js/config.js` and set the public project URL and anon key. The local
`js/config.js` is ignored by Git so each collaborator can use their own
development project. Never use a Supabase service-role key in browser code.

> The backend serves both the static front end and the REST API on one port. Keep `transformers<4.47` pinned: newer `transformers` removes the `T5Tokenizer.build_inputs_with_special_tokens` method that benepar's retokenizer relies on.

The requirements also install `inflect`, which supplies deterministic English
noun morphology (productive rules plus maintained lexical exceptions). The
matrix uses it to reject malformed plurals such as `foots`, `childs`, and
`sheeps`, while accepting alternatives such as `cacti`/`cactuses`,
`people`/`persons`, and invariant nouns such as `sheep`. It is used for lexical
form validation only; grammatical number still comes from the parser's POS
tags.

### Editor highlighting and history

The workbench accepts single sentences and multi-sentence passages. After an
analysis, incorrect words are rendered in red and valid words remain black.
The selected sentence receives a light background highlight. Because a native
textarea cannot style individual words, the UI uses a safe, positioned
highlight layer while the textarea is locked. Double-clicking switches to the
normal textarea so the native blinking caret remains available; leaving the
editor locks it again and re-analyzes changed text.

Highlight spans are recomputed in memory from the analysis payload and are not
stored in the database. Authenticated submissions are saved to Supabase
`analysis_history`; replay, sentence navigation, and failed inserts do not create false
duplicate/success states; a successfully saved sentence is also not inserted
again later in the same browser session. Apply
`supabase/migrations/20260916000000_analysis_history.sql` to create the table
and its user-scoped row-level security policies.

## REST API

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/` | GET | static front end (`index.html`, `js/`, `css/`) |
| `/api/health` | GET | model/pipeline availability (503 with install hints if models are missing) |
| `/api/parse` | POST | `{"text": "<sentence>"}` → full JSON payload |

The `POST /api/parse` payload bundles the complete precomputed analysis. Accepts `{"text": "<text>", "sentence_index": <0-based int, optional>}`; when the text contains a paragraph, `sentence_index` selects which sentence to analyze (defaults to 0). `meta.target_sentence` and `parse.sentences` give the selected sentence and the full segmentation with character offsets (used by the UI so clicking any sentence loads its tree):

- `parse.tokens` — spaCy token metadata (`t`, `pos`, `tag`, `dep`, `head`).
- `parse.parse_string` — benepar's `span._.parse_string` for the selected tree.
- `parse.sentences` — `[{ordinal, start, end, text}]` char-offset spans over the input.
- `tree` — nested node graph `{id, type, span, surface, children?, pos?}`.
- `nodes` — flat `id -> node` map.
- `node_details` — precomputed XAI explanation per node: `role`, `constraint`, `status` (`valid`/`error`/`unlisted`), `text`, parent/children.
- `summary` — counts + verdict + fired constraints.
- `explainers` — `basic` and `contrastive` (deterministic templates); `surprisal`, `perturbation`, `llm_note` are `null` by design.
- `meta` — `deterministic: true`, model names, sentence count, `target_sentence`.

## Architecture and data flow

SynTutor is split into a browser client and a small Python backend. The
backend serves the static files and exposes the parsing API, so the application
runs without a frontend build tool or a web framework.

```text
Browser
  index.html + style.css
        |
        v
  main.js (FSM, request orchestration, highlighting, and history)
    |
  auth.js (Supabase session and sign-in/register actions)
    |                    \
    v                     v
  renderer.js          ui.js
  canvas tree          DOM explanations, verdicts, logs
        |
        | POST /api/parse {text, sentence_index?}
        v
Python server/app.py
    |
    +--> parse_engine.py
    |      spaCy tokenization/POS + benepar constituency tree
    |      parse string -> serializable node graph
    |
    +--> matrix.py
           deterministic parent-child rule evaluation
           node explanations, remediation, summary
```

The browser keeps each complete response in the in-memory `session` object.
Selecting or hovering a node is therefore a local operation; it does not
trigger another parse request. Editing the textarea and submitting changed
text starts a new full pipeline run.

## The 7-stage pipeline

SynTutor implements the spec's Input–Process–Output architecture with a dual-loop feedback mechanism. The active stage is lit in the header strip.

| # | Stage | Impl |
|---|-------|------|
| 1 | **User Input** — raw English sentence or passage | `ui.js`, `main.js` |
| 2 | **Request /api/parse** — front end posts the text, receives the JSON payload | `main.js` |
| 3 | **Tokenization & POS** — spaCy (`en_core_web_md`) | `parse_engine.py` |
| 4 | **Parsing** — benepar neural constituency parse; tree extracted from `span._.parse_string` | `parse_engine.py` |
| 5 | **XAI validation** — deterministic evaluation of every parent→child edge against the constraint matrix | `matrix.py` |
| 6 | **Explanation generation** — plain-language `f_valid`/`f_error` + basic & contrastive summaries | `matrix.py`, `app.py` |
| 7 | **UI Canvas & Feedback Loop** — interactive tree, edge color-coding, cached node explanations | `renderer.js`, `main.js` |

## The Linguistic Constraint Matrix

For every edge \((v_d \to v_p)\) the system evaluates:

\[
E(v_d, v_p) = \begin{cases}
f_{valid}(v_d, v_p), & (v_d \to v_p) \in \mathcal C\\[2pt]
f_{error}(v_d, v_p, \delta), & (v_d \to v_p) \notin \mathcal C\\[2pt]
\text{unlisted (valid-by-default)}, & \text{no rule in } \mathcal C
\end{cases}
\]

where membership in \(\mathcal C\) is decided by a hand-authored **rule matrix over Penn POS classes** (parent class × child class → role). Feature constraints are verified on the tree by deterministic head extraction and feature functions:

| δ | Checks | Demo |
|----|--------|------|
| `C-SUBJECT-AGREEMENT` | subject person/number vs. finite verb/aux form | `The boys runs.` · `John are running.` |
| `C-DETERMINER-AGREEMENT` | determiner `numreq` vs. head-noun number | `These boy runs.` · `A dogs bark.` |
| `C-NOUN-FORM` | observed plural vs. accepted singular/plural morphology | `These foots hurt.` · `The childs play.` · `The mens are here.` |
| `C-AUX-FORM` | aux selects the verb form: modal/`do`→base, `have`→past participle, `be`→participle | `Mary will eats.` · `The girl has eat.` |
| `C-VERB-FORM` | rejects irregular verbs regularized as `-ed` and past-tense forms used as participles | `becomed` · `have came` |
| `C-TENSE-FINITE` | a main clause requires a finite predicate | `The boy running.` (fragment root) |
| `C-MOD-POS`, `C-DET-STACK`, `C-HEAD-NOUN` | structural: modifier-before-head, single determiner per NP, determiner-licensed head | `car red` · `The my book` · `I hate your.` |
| `C-PRONOUN-CASE` | nominative subject vs. objective object/preposition form | `Me likes music.` · `to she` |
| `C-ADJ-ADV` | adjective where an adverb is required (incl. flat adverbs, after action verbs) | `runs quick` · `sings beautiful` |
| `C-ARTICLE`, `C-ARTICLE-MISMATCH` | missing determiner before a singular count noun; phonetic `a`/`an` | `Dog is barking.` · `a elephant` |
| `C-QUANTIFIER`, `C-COMPARATIVE-DOUBLE` | `less/fewer`, `much/many`; `more smarter` | `less cookies` · `more smarter` |
| `C-CAPITALIZATION` | sentence-initial capital letter | `he runs fast.` |
| `C-SMALL-CLAUSE`, `C-INFINITIVAL-COMPLEMENT`, `C-ADVERBIAL-COMPLEMENT` | licensed complement structures | `made her happy` · `want to go` · `an hour ago` |
| `C-UNLISTED` | edge has no matrix row — reported unrated (valid-by-default) | — |

Each explanation is tagged with its δ. Clicking any node reads its explanation from the precomputed `node_details` map held in session memory — **no re-parse on node click**.

## State machine & dual-loop feedback

`IDLE → PROCESSING → VIEWING ⇄ EXPLORING → END`

- **Idle** — waiting for input.
- **Processing** — composite: `Request → Tokenize/POS → Parse → XAIValidate → ExplanationComputed → OutputReady`.
- **Viewing** — tree rendered, basic explanation auto-shown. Node click → **Exploring**; edited submission → **Processing**; exit → **End**.
- **Exploring** — cached node explanations. "Back to syntax tree" returns to **Viewing**.

- **Interaction Loop (lightweight)** — clicking a node looks up its precomputed explanation by node ID in local session memory; no HTTP request.
- **Re-Entry Loop (full restart)** — editing and resubmitting restarts the pipeline. Auto-correction is intentionally prohibited: SynTutor shows the violation and a deterministic correction *suggestion* (contrastive explainer), but the learner fixes the text.

Transitions are logged live in the right-hand panel.

```
server/
  parse_engine.py        spaCy tokenization/POS + benepar parse-string -> node graph
  matrix.py              Linguistic Constraint Matrix + deterministic XAI evaluation
  app.py                 stdlib HTTP server: static files + /api/parse + /api/health
index.html               UI shell
css/style.css            styling
js/
  renderer.js            canvas layout, edges, hitboxes, pan/zoom
  ui.js                  DOM views (explainer/diagnostic/log/pipeline UI)
  main.js                FSM + pipeline, highlighting, auth, and history
  auth.js                Supabase client and sign-in/register session handling
package.json             npm run serve -> python3 server/app.py
docs/
  THESIS.md              design specification (input document)
  RULES.md               rule-matrix inventory
  ARCHITECTURE.md        implementation reference
  README.md              this file
FEATURES.md              feature inventory, progress, and known gaps
```

Tests are excluded per the project spec. The maintained verification command
is `npm run audit`, which runs the gold-corpus rule coverage audit without
starting HTTP; runtime verification can be done through `/api/health` and
`/api/parse`.
